# 业务文档

## 1. 需求背景

自媒体运营需要把同一篇内容分发到多个平台。手动逐个平台排版、配图、发布耗时长且易出错。本工具已实现**小红书图文笔记自动发布**，以及**微信公众号新闻采集→繁转简→推草稿**两条独立链路。

## 3. 使用场景

- 非技术用户通过可视化界面完成配置、生成、编辑与发布。
- 个人博主按主题快速产出小红书图文笔记。
- 已有成稿（人工或他处生成）时，一键发布到小红书。
- 先干跑生成内容与配图，确认后再发布。
- 运营者定时采集财经新闻，繁转简后推送到公众号草稿箱备用。

## 4. 操作流程

### 4.1 首次准备

1. 安装依赖：`pip install -r requirements.txt`
2. 复制 `.env.example` 为 `.env`，填入生成后端密钥与图库密钥。
3. 若被 Windows Defender 拦截（程序报 `leakless.exe` 相关错误）：以管理员运行 `powershell -ExecutionPolicy Bypass -File .\scripts\allow_defender.ps1`（脚本会排除 Temp 下的 `leakless-amd64-*` 目录），然后到 Defender「保护历史记录」把 `leakless.exe` 条目「允许/还原」。
4. 启动 `xiaohongshu-mcp-windows-amd64.exe`（首次会下载无头浏览器，约 150MB）。
5. 在界面点「扫码登录」，用小红书 App 扫描界面内二维码完成登录（只需一次）。

> 若点「扫码登录」被 Windows SmartScreen 拦截（未签名程序的“已保护你的电脑”提示）：右键 `xiaohongshu-*.exe` → 属性 → 勾选「解除锁定」；`run_gui.bat` 启动时也会自动解除锁定。MCP 在线时登录走界面内二维码，不启动额外的登录程序。

### 4.2 可视化界面（推荐）

1. 双击 `run_gui.bat` 打开窗口（首次会自动安装 `customtkinter`）。
2. 顶部标题右侧可切换 **小红书 / 公众号** 两个平台：小红书下含「发布 / 自动 / 配置」三个页签，公众号为独立面板（窗口标题会跟随所选平台变化）。
3. 右上角可切换 `深色 / 浅色 / 跟随系统`，选择会记住。
4. 首次使用切到「配置」页签，填写密钥后点「保存配置」（可先点「测试图库」「测试生成」验证连通）。
   同时可配置生成规则：配图数量范围、去重天数与阈值、是否开启实时热点参考；并在下方编辑「提示词」后保存。
5. 回到「发布」页签，点「启动服务」等待状态显示“服务在线”；未登录时点「扫码登录」，界面会弹出二维码，用小红书 App 扫码即可（成功后窗口自动关闭）。
6. 输入主题、选择生成后端与配图数量，点「生成并配图」。
7. 在预览区修改标题、正文、标签（正文注意不超过 1000 字）。
8. 选择可见范围、是否原创，点「发布」，结果以顶部提示与日志区显示。

**如何确认已登录：**

- 服务栏的登录指示显示绿点 +「已登录」即已登录；橙点「未登录」需重新扫码。
- 也可点「检查登录」，在日志区查看返回结果（用户名可能显示为写死的 `xiaohongshu-mcp`，属正常）。
- 扫码成功时二维码窗口会自动关闭，并弹出「登录成功」提示。
- 登录态保存在项目根目录 `cookies.json`，重启 MCP 服务后一般仍在。**同一账号不要在其他网页端再登录**，否则会被踢下线。

### 4.3 命令行发布

```bash
# 按主题生成并发布（默认 OpenAI 后端）
python publish.py "春天露营装备推荐"

# 指定 Anthropic 后端
python publish.py "春天露营装备推荐" --gen anthropic

# 只生成不发布，先预览
python publish.py "春天露营装备推荐" --dry-run

# 指定配图数量（默认按配置范围随机）
python publish.py "春天露营装备推荐" --count 4

# 发布已有内容
python publish.py --from-json articles/20260911_180216_note/article.json
```

### 4.4 生成规则说明

- **人设与文风**：内置“30 岁职场人”第一人称口吻，要求真实细节、口语化、带情绪，禁止 AI 套话；可在界面编辑提示词调整。
- **防重复**：生成前把最近 7 天标题/摘要注入提示词，生成后再用相似度校验，超过阈值（默认 30%）自动重新生成，最多 3 次；仍未达标则采用相似度最低的一篇并在日志告警。
- **实时参考**：按主题抓取小红书真实笔记标题作为“热点参考”，仅借鉴选题角度与标题写法，禁止照抄；MCP 离线时自动跳过。
- **标题与标签**：标题≤20 字、夸张有冲突感；标签 4-6 个、蹭热点情绪（打工人、职场PUA、35 岁危机等）。
- **配图**：在配置范围内随机数量，关键词按内容顺序排列，第 1 个为封面；抓取后自动压缩为 <500KB JPEG。

### 4.5 全自动发布

在「自动」页签配置后启动常驻，即可无人值守定时发布。

1. 使用自动前先确认已「启动服务」并「已登录」。
2. 配置：
   - **配置页**：每日发布上限（自动+手动成功都计入）；
   - **自动页**：发布时段（如 `09:30,15:00`）、自动发布范围、选题来源、领域关键词、AI 选题数量、检查间隔。
3. 选题池：`topics.txt` 每行一个选题（可在「自动」页签编辑保存）；发布成功后自动移除。
   - `pool_first`：先用选题池，池空则由 AI 按领域生成；
   - `ai`：完全由 AI 生成选题；
   - `pool_only`：仅用选题池，用完停止。
4. 操作按钮：
   - 「启动常驻」：按配置时段定时发布；状态栏显示“下次触发时间”和“今日已发布 X/上限 Y”；
   - 「立即执行一次」：立即发布一篇，**遵守每日上限**，达上限会提示并跳过；
   - 「强制执行一次」：**忽略每日上限**发布一篇（仍校验服务与登录）；
   - 「停止」：结束常驻。
5. 命令行等价用法：`python auto.py --once`、`python auto.py --once --force`、`python auto.py --loop`。

**规则与安全**：
- **上限口径**：每日上限统计“发布成功”的条数（自动与手动都算），生成失败/发布失败不计入；数据存于 `logs/publish_history.jsonl`。
- **不补发**：常驻启动时当天已过的时段直接跳过，不会一开机连发；错过请用「强制执行一次」。
- **每个时段一次性**：无论成功、失败、达上限或未登录，该时段当天不再重复触发（避免频繁重试）。
- **配置即时生效**：修改后点「保存自动设置」，常驻下一轮检查即生效，无需重启。
- 未登录无法自动扫码 → 记日志并停止该次，需在界面扫码后手动执行。
- 自动发布建议先用「仅自己可见」验证几篇再改「公开可见」。
- 日志位于 `logs/auto_YYYYMMDD.log`。

### 4.6 配图来源（汽车之家 / 图库）

- **自动判断**（默认 `IMAGE_SOURCE=auto`）：主题或中文关键词命中车型（见映射表）或含汽车词 → 走**汽车之家**按车型抓图；否则走 Pexels/Unsplash 图库。
- **汽车之家**：按 `data/car_series.json` 里的“车型名 → 车系ID”映射抓取，分类由 `CAR_IMAGE_CATEGORIES` 控制（默认 `外观,内饰`）；抓取失败自动回退图库，不阻塞发布。
- **维护映射表**：运行 `python scripts/build_car_map.py` 抓取汽车之家车型表并更新内置热门车型；也可 `python scripts/build_car_map.py 车型名` 追加指定车型，或手工编辑 `data/car_series.json`。
- **合规提示**：汽车之家图片多为版权图，用于小红书存在版权与平台风控风险，请自行评估；重要内容建议用官方/自拍图。
- 结果会缓存到 `data/cache/images/`（12 小时），减少请求。

### 4.7 微信公众号（新闻采集发布）

整条链路独立于小红书，互不影响。公众号为**推草稿 + 人工发布**模式。

**首次准备**

1. 安装 Chrome/Edge 扩展 [Wechatsync](https://www.wechatsync.com/#install)，在扩展设置里启用「同步桥接 / MCP 连接」并复制 Token。
2. 浏览器里登录公众号后台，确保扩展能识别到公众号账号（`wechatsync auth weixin` 显示「已登录」）。
3. `npm install -g @wechatsync/cli`，把 Token 填入 `.env` 的 `WECHATSYNC_TOKEN`。
4. 在 `.env` 配置 `MINIMAX_API_KEY`（繁转简），默认使用国内站 `https://api.minimaxi.com/v1`。

**界面操作**

1. 在顶部把平台切到「公众号」，填写并「保存配置」（Wechatsync Token、目标平台、MiniMax 密钥与地址、新闻站点、抓取数量范围、AI 优先）。
2. 点「检测环境」确认 wechatsync 可用；点「检查登录」确认公众号已登录。
3. **手动发布一条**：点「刷新候选」加载当前站点候选到下拉框（形如 `#1 标题（来源）`）；下拉框**只列未发布**的候选，已发布的会自动排除（状态记于 `logs/wechat_publish_history.jsonl`）。选中一条后可点「打开原文」用浏览器打开该条源新闻链接；点「发布选中」则推送草稿，成功后该条从下拉框消失。
4. 「预览候选」可在日志里查看全部候选。
5. 「干跑（不推送）」抓取、翻译、下载配图并留档到 `wechat_articles/`，可在本地核对 Markdown 与图片。
6. 「抓取并发布」为随机批量模式：按数量随机抽取并逐篇推送到公众号草稿箱（发布过的原文会被记录，后续不会再出现在下拉框）。

**命令行**

```bash
python wechat_publish.py --check          # 检查 wechatsync
python wechat_publish.py --auth           # 检查公众号登录
python wechat_publish.py --list           # 只看候选
python wechat_publish.py --dry-run        # 抓取+翻译+留档，不推送
python wechat_publish.py                  # 抓取并推送草稿
python wechat_publish.py --from-md a.md   # 直接发布本地 Markdown
```

**规则**

- **随机选题**：每次在 `[NEWS_PICK_MIN, NEWS_PICK_MAX]`（默认 3~5）内随机取篇数；命中 `NEWS_AI_KEYWORDS` 的 AI 相关新闻优先，但仍**在候选中随机**，绝不取列表前几条。
- **图文与去广告**：只白名单采集正文段落与正文图片，广告（`inarticle-ad`/`ad-container`/native-ad）、视频/相关推荐等模块全部丢弃；图片下载压缩为 `<500KB` JPEG 并保持图文顺序。
- **杂质清理（自动，无需人工）**：
  - 尾部截断：`NEWS_STRIP_PATTERNS` 命中处起截断，去掉来源/推广尾巴（如「網址:」「阿思達克財經…」）；
  - 整段丢弃：被 `<em>` 包裹的段落（作者署名、订阅/推广引导，如咏竹坊「李世達」「欲訂閱…請點擊這裡」）与命中 `NEWS_DROP_KEYWORDS` 的段落直接删；
  - 末尾短署名：`NEWS_BYLINE_MAX_CHARS`（默认 6）内、无标点的末尾中文短名自动删（最多 2 段，至少保留 1 段正文）；
  - MiniMax 顺带清理：繁转简时一并删除署名/订阅/推广/免责等非正文段，不确定的保留、正文不改写。
- **无图自动配图**：正文一张图都没有时，先用 MiniMax 从**标题+正文**提取公司名/人名/关键词，**公司名、人名优先**检索图库，补 3~5 张图（`NEWS_AUTO_IMAGE_MIN/MAX`）均匀插在段落之间；图库**完全没命中**时改用 MiniMax 文生图生成（最多 `NEWS_AUTO_IMAGE_GEN_MAX` 张，默认 2；单张超时 `MINIMAX_IMAGE_TIMEOUT` 默认 60s）；生成慢或失败则**跳过配图、继续发布**，不会卡住（`MINIMAX_IMAGE_MODEL` 留空则关闭生成）。
- **封面**：文章**自身有图**就用首图；文章**自身无图**则用 **MiniMax 文生图**按标题生成封面（16:9，模型 `MINIMAX_IMAGE_MODEL`，留空则关闭）；生成失败用配置的 `WECHAT_DEFAULT_COVER`；都没有则无封面发布（不阻断）。封面**不再从图库扒取**。
- **繁转简**：MiniMax 逐段转换，要求只做字形转换、不改写；**标题与正文都转**，作者与来源保留原文；图片占位符异常时回退逐段翻译。
- **封面**：正文无图时，用 MiniMax 生成英文关键词从图库抓一张封面；失败则不带封面推送。
- **新增站点**：在 `sites/` 下新建模块并暴露 `SITE`（`NewsSite` 实例）即自动注册，页签下拉即可切换。现有源：Yahoo 香港財經（繁中）、Anthropic 新闻（英文）、The Independent（英文，**需 `pip install playwright` + 本机 Edge/Chrome**）、TechCrunch（英文，纯 HTTP）、Ars Technica AI 频道（英文，纯 HTTP；主源抓不到时自动降级到其 RSS，候选会少一些）、The Rundown AI（英文，纯 HTTP，**新闻**与**简报**两个入口：新闻干净短小、简报是每日长文且已自动过滤赞助段）、AIBase 资讯（**简体中文，不走翻译**，候选固定 20 条、自带中文推广段过滤）。除 AIBase 外的英文源与繁中源都依赖 MiniMax 翻译为简体；作者/来源字段保持原文不翻译。

## 5. 注意事项

- 小红书标题不超过 20 字、正文不超过 1000 字，超限脚本直接报错，不会硬发。
- 图片自动压缩为小于 500KB 的 JPEG，文件名使用 ASCII，避免中文路径问题。
- 同一小红书账号不要在其他网页端重复登录，否则会挤掉 MCP 登录态。
- 发布若长时间“处理中”会在 240 秒后超时提示，请到小红书 App 确认是否已发出，避免重复发布；排查可在配置页把「静默启动浏览器」设为 `false`，重新启动服务后会显示浏览器窗口，便于观察卡在哪一步。
- 上游 v2.5.0 曾有「回点标题输入框失败」导致发布卡死的 Bug，已通过**编译社区补丁 PR #846** 修复（原版已备份），发布实测成功。
- 因上游「实时热点参考」搜索接口近期不稳定，默认已**关闭**（`XHS_REFERENCE_ENABLED=false`），不影响发布；需要时可再开启。
- 正文/标签/配图数量现可在配置页自由调整（`正文目标字数 / 标签数量上限 / 配图数量上下限`），不再需要为规避 Bug 而刻意缩短。
- 新号建议先完成实名认证，避免触发风控提示。
- **公众号依赖浏览器在线**：Wechatsync 走 Chrome 扩展的浏览器登录态，发布时需保持 Chrome 打开且扩展已连上桥接；CLI 独占 `SYNC_WS_PORT`（默认 9527），故新闻发布为串行。
- **公众号只到草稿箱**：Wechatsync 默认存草稿，不会自动群发；请在公众号后台人工复核后发布。
- **版权提示**：转载 Yahoo/AASTOCKS 等外部财经新闻到自有公众号存在版权与平台风控风险，请自行评估；建议人工复核后再发布。
- **繁转简保真**：MiniMax 属生成式，可能轻微改动措辞；提示词要求逐字转换，仍以草稿箱人工复核为准。
- **公众号登录检查异常**：若提示「检查失败 / Invalid or missing token」，是扩展里的 Token 与「Wechatsync Token」不一致，重新复制粘贴并保存；若显示「未登录」但后台已登录，确认「目标平台」为 `weixin`（留空会误报）。
- **检查登录不再卡死**：子进程窗口默认隐藏；检查约 45 秒超时会自动终止并恢复，重试前会自动清理残留进程，无需重启 app。
- **「扩展未连接同步桥接」怎么办**：点「检测登录」/发布时若看到这句话（或一直超时），意思是 Chrome 里的「文章同步助手」扩展没有接上本地桥接，**与 VPN/代理无关**。处置顺序：① Chrome 打开该扩展 → 把「MCP 连接」关掉再打开（或 `chrome://extensions` 点「重新加载」）；② 确认扩展里的服务器地址是 `ws://localhost:9527`；③ 仍不行则重启 Chrome。自检：浏览器访问 `http://localhost:9528/status`，出现 `"connected":true` 才算连上。现在这种情况会**立刻报错并顺手清理占用端口的旧进程**，不再白等；若日志里出现 wechatsync 的「安装步骤」指引，等价于同一原因。
- **配置留空即用默认**：抓取数量、候选上限、图片上限等数值项留空不会报错，会按默认值处理（如候选上限 60、抓取 3~5）。
