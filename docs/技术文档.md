# 技术文档

## 1. 架构概览

```
入口  ├─ GUI(app.py，CustomTkinter，双击 run_gui.bat)  ─┐
      ├─ CLI(publish.py)                               ─┤
      └─ 自动(auto.py，--once / --loop)                 ─┤
                                                        ▼
                     publish.build_article()  生成→配图
                       → generate.generate_unique()  提示词 + 去重重试
                            ├─ prompts/note_prompt.txt  用户自定义提示词
                            ├─ history.py               近 N 天文章 + 相似度
                            └─ 模型接口 [OpenAI /v1/chat/completions | Anthropic /v1/messages]
                       → images.py    配图 [Pexels → Unsplash → 本地图库回退] + Pillow 压缩
                     publish.run()    留档→发布
                       → xhs.py       [MCP SDK: search_feeds 参考 / publish_content 发布]
                       → articles/    留档 article.json + 图片
                     auto.py 自动编排：定时→选题→(build_article)→发布，状态写 logs/auto_state.json
```

公众号链路（独立于小红书）：

```
入口  ├─ GUI(app.py 顶部「小红书/公众号」平台切换)  ─┐
      └─ CLI(wechat_publish.py)      ─┤
                                     ▼
        news_pipeline.run()  编排：候选→随机选取→抓正文→下载配图→繁转简→推草稿
          ├─ sites/          插件：[base 接口 | __init__ 自动注册 | yahoo_hk_finance]
          ├─ translator.py   MiniMax(OpenAI 兼容) 繁转简 + 封面关键词
          ├─ images.py       (复用) 无图时抓图库封面
          └─ wechat.py       调 wechatsync sync -p weixin 推公众号草稿
        → wechat_articles/   留档 article.md + img_*.jpg + meta.json
```

`sites/` 采用插件式自动注册：新增站点只需放一个模块并暴露 `SITE`。`wechat.py` 通过 Chrome 扩展（Wechatsync）的浏览器登录态发布，默认存草稿。

`auto.py` 复用 `publish` 与 `generate`，GUI 与 CLI 共用 `publish.build_article()` / `publish.run()`。

## 2. 模块职责

| 文件 | 职责 |
|------|------|
| `app.py` | CustomTkinter 可视化界面：配置/提示词/选题池编辑、服务登录管理、生成预览发布、自动常驻控制 |
| `auto.py` | 全自动引擎：`run_once()` 单次、`loop()` 常驻定时、状态与日志、MCP 自启、AI 选题 |
| `publish.py` | 编排 `build_article()`/`run()`（CLI 与 GUI 共用，支持可选 `on_step` 阶段回调）+ 命令行入口 |
| `generate.py` | 内置/加载提示词、两种生成后端、JSON 提取（兼容 `<think>`）、长度校验、`generate_unique()` 去重重试、`suggest_topics()` 选题 |
| `history.py` | 扫描近 N 天文章、`difflib` 相似度计算与去重判定 |
| `images.py` | 图片源编排：图库（Pexels/Unsplash）与汽车之家车系图、下载压缩、缓存、回退 |
| `xhs.py` | MCP SDK：登录检查/二维码、`search_feeds` 参考、`publish_content` 发布 |
| `wechat.py` | 公众号发布：解析 wechatsync CLI 命令、同步 Markdown 到公众号草稿（Windows `.cmd` 兼容、stdout 解析成败） |
| `translator.py` | MiniMax OpenAI 兼容接口繁转简：整篇占位符翻译 + 分段，失败回退逐段；`entity_terms()` 从标题+正文提取公司/人名/关键词供配图 |
| `imagegen.py` | 文生图：`generate_cover()` 按标题生成 16:9 封面；`generate_body_images()` 图库无命中时生成正文配图（均落盘 `cover_ai.jpg` / `auto_gen_N.jpg`） |
| `news_pipeline.py` | 新闻发布编排：候选随机选取（AI 优先）、下载压缩配图、繁转简、封面、推草稿、留档与历史 |
| `wechat_publish.py` | 公众号命令行入口（`--list`/`--dry-run`/`--from-md`/`--auth`/`--check`） |
| `sites/base.py` | 新闻站点插件基类：`NewsItem`/`TextBlock`/`ImageBlock`/`NewsArticle`/`NewsSite` |
| `sites/__init__.py` | 插件自动发现与注册（`pkgutil`），`available_sites()`/`get_site()` |
| `sites/yahoo_hk_finance.py` | Yahoo 香港財經插件：列表与正文解析、白名单去广告、图片提取、内嵌 HTML 自检 |
| `run_gui.bat` | 双击启动 GUI（优先 `pythonw` 无黑窗） |
| `scripts/allow_defender.ps1` | Defender 误报处理（需管理员） |
| `docs/` | 业务文档与技术文档 |

### 4.1 GUI 配置读写

- 读取：`dotenv_values(ENV_PATH)` 载入表单；启动时 `load_dotenv(override=True)` 写入进程环境。
- 保存：`write_env()` 按 key 逐行更新 `.env`，保留注释与未知项，缺失键追加末尾。
- 密钥字段默认掩码显示，可勾选「显示密钥」切换明文（`CTkEntry.configure(show=...)`）。
- 「测试图库/测试生成」会先把表单值写入 `os.environ` 再调用，未保存也能验证。
- 主题切换即时调用 `ctk.set_appearance_mode()`，并写入 `.env` 的 `UI_APPEARANCE`。

### 4.2 GUI 线程模型

- 所有耗时操作（生成、搜图、发布、起服务）在 `threading.Thread` 中执行。
- 结果通过 `queue.Queue` 投递可调用对象，主线程 `root.after(100ms)` 轮询执行，保证 UI 不阻塞。
- 任务执行期间按钮禁用并显示动态文字（`处理中·` 循环动画），完成后恢复原标题。
- 顶栏下方有全局不确定进度条（`CTkProgressBar` indeterminate），由忙碌计数 `_push_busy()/_pop_busy()` 统一控制，所有耗时任务自动纳入。
- 发布页「流程」步骤条：`生成文案 → 配图 → 留档 → 发布`，进行中=黄、完成=绿（✓）、失败=红（✕）；`publish.build_article()/run()` 通过可选 `on_step` 回调上报阶段。
- 状态点在检测/运行时脉冲：登录检查中、自动常驻运行中。
- 启动服务等待期间显示“正在启动服务…已等待 Ns”，配合进度条与状态点。
- MCP 服务启动后轮询端口 18060，就绪后更新状态栏；状态每 5 秒自动刷新。
- 服务在线后自动调用一次 `check_login_status`，在服务栏显示登录状态（已登录/未登录），并随检查/扫码更新。
- 扫码登录：取到二维码后弹出 `CTkToplevel` 显示 `CTkImage`，每 2 秒轮询登录状态，成功自动关闭。
- 操作反馈使用顶部轻量 toast（`CTkLabel` + `place`），替代弹窗。

### 4.3 界面框架

- 基于 `customtkinter`（>=5.2.0），默认蓝色主题，支持深/浅色。
- 关键控件：`CTkTabview`（小红书下的发布/自动/配置）、`CTkScrollableFrame`、`CTkTextbox`、`CTkComboBox`、`CTkOptionMenu`、`CTkSwitch`、`CTkSegmentedButton`、`CTkImage`（缩略图）。
- **顶层平台切换**：顶栏标题右侧放 `CTkSegmentedButton`（小红书/公众号），窗口与顶栏标题跟随所选平台；内容区两个容器互斥显示——`self.xhs_tabview`（发布/自动/配置）与 `self.wechat_panel`（公众号面板），由 `_on_platform_change()` 切换 `pack/pack_forget`。四个页签的构建方法（`_build_publish_tab/_build_auto_tab/_build_config_tab/_build_wechat_tab`）不变，仅容器改挂载点。
- 「公众号」面板独立于小红书：拥有自己的 `wechat_vars` 配置表单（Wechatsync/MiniMax/抓取项）、环境与登录指示、独立日志区，复用通用 `_card`/`_run_task`/`_toast`；站点下拉由 `sites.available_sites()` 动态生成。配置经 `write_env()` 写回 `.env`，不参与 `CONFIG_FIELDS`。
- 「公众号」操作区含**候选下拉框**：点「刷新候选」调 `news_pipeline.list_candidates()`，用 `published_source_urls()` 过滤掉已发布项后填充；「发布选中」调 `news_pipeline.run(selected=[item])` 单篇发布，成功后自动刷新下拉；「打开原文」用 `webbrowser.open(item.url)` 打开选中候选的源新闻链接（选中映射由 `_wechat_selected_item()` 统一解析 `#序号` 前缀）。另保留「预览候选」「干跑」「抓取并发布（随机批量）」。

## 5. 外部接口

### 5.1 内容生成

- OpenAI 兼容：`POST {OPENAI_BASE_URL}/chat/completions`，`Authorization: Bearer <key>`。
- Anthropic：`POST {ANTHROPIC_BASE_URL}/v1/messages`，`x-api-key` + `anthropic-version: 2023-06-01`。
- 两者共用同一提示词，要求模型仅返回 JSON：`{title, content, tags[], image_keywords[]}`。

### 5.2 图片源

- Pexels：`GET https://api.pexels.com/v1/search`，请求头 `Authorization: <key>`，取 `src.large`。
- Unsplash：`GET https://api.unsplash.com/search/photos`，请求头 `Authorization: Client-ID <key>`，取 `urls.regular`。
- **汽车之家**：`GET https://car.autohome.com.cn/pic/series/<车系ID>-<分类>.html`（分类 `1`=外观、`10`=中控、`3`=座椅、`12`=细节），正则提取 `car2.autoimg.cn` 图片地址，把尺寸前缀替换为 `1000x0_0_q95_c42_` 取大图；下载带 `Referer: https://car.autohome.com.cn/`。
- **来源选择**：`images.resolve_sources()`——`IMAGE_SOURCE=auto` 时，命中车型映射或主题含汽车词则 `autohome→pexels→unsplash`，否则 `pexels→unsplash`；也可显式配置优先级列表。
- **车型映射**：`data/car_series.json`（`车型名 → {autohome: 车系ID}`）；`scripts/build_car_map.py` 扫描汽车之家静态车型表生成/追加。
- **缓存**：`data/cache/images/<sha1>.json`，TTL 12 小时。
- 均失败时回退 `assets/gallery` 本地目录。

### 5.2.1 汽车主题判断

- `images.is_car_context(topic, keywords_zh)`：中文关键词命中映射表，或主题包含汽车词（`汽车/试驾/提车/新能源/续航/特斯拉/小米su7` 等）。
- 提示词要求模型在 `image_keywords_zh` 输出“具体车型+视角”（如 `小米SU7 外观`），供汽车之家按车系抓图。

### 5.3 小红书 MCP

- 传输：Streamable HTTP，`http://localhost:18060/mcp`。
- 调用工具：
  - `check_login_status`：发布前登录检查，也用于登录轮询。
  - `get_login_qrcode`：获取登录二维码，返回 Base64 图片；兼容 MCP ImageContent 与文本内嵌 data URL 两种形式。
  - `publish_content`：参数 `title`、`content`、`images`（本地绝对路径）、`tags`、`visibility`、`is_original`。
  - `search_feeds`：按关键词搜索，返回 JSON（`feeds[].noteCard.displayTitle`）；`xhs.search_feeds()` 提取标题列表用于实时参考。
- **登录方式**：优先用 MCP 的 `get_login_qrcode` 在界面内展示二维码并轮询 `check_login_status`；仅当 MCP 未在线或取码失败时，才回退启动 `xiaohongshu-login-windows-amd64.exe`。
- **超时**：`_call_tool()` 统一传 `read_timeout_seconds`——状态/二维码 60s、搜索 90s、`publish_content` **330s**（大于服务端 300s 内部上限）；超时抛中文 `XhsError` 并提示“可能仍在后台进行，请到 App 确认”，避免界面永久“处理中”。
- QR 解析：`xhs._extract_qrcode_base64()` 先取图片内容，再从文本里匹配 `data:image/...;base64,` 或长 base64 串。

### 5.4 生成与去重

- **提示词**：`generate.load_prompt_template()` 读取 `PROMPT_FILE`（默认 `prompts/note_prompt.txt`），缺省用内置模板；占位符 `{topic} {recent} {reference} {image_count} {title_max} {content_max} {dedup_days} {dedup_threshold}`。
- **去重**：`history.recent_texts(days)` 读取 `articles/*/article.json`，`similarity()` 用标准库 `difflib.SequenceMatcher` 归一化比对；`generate.generate_unique()` 循环生成，`max_similarity <= DEDUP_THRESHOLD` 才采用，否则重试，最终取相似度最低者并告警。
- **实时参考**：`publish.build_reference()` 调 `xhs.search_feeds(topic, count)`，把标题列表注入提示词；MCP 异常时降级为“（无）”，不阻塞。
- **配图数量**：`publish.pick_image_count()` 在 `[MIN, MAX]` 内随机；`image_keywords` 顺序即配图顺序，首个为封面。
- **推理模型兼容**：`_extract_json()` 先剥离 `<think>...</think>`（含未闭合），再扫描首个含 `title` 的可解析 JSON；OpenAI 路径设置 `max_tokens` 避免推理截断。
- **模型区域**：MiniMax 国内站为 `https://api.minimaxi.com/v1`，国际站 `https://api.minimax.io/v1`；密钥与站点需匹配。

### 5.5 全自动引擎（auto.py）

- `run_once(force=False)`：先按已发布数校验每日上限（`force=True` 忽略上限）→ `ensure_service()` → `ensure_login()` → `pick_topic()` → `publish.run()` → 成功后 `remove_pool_topic()`。
- `loop(stop_event, log)`：常驻线程，每 `AUTO_CHECK_INTERVAL_SEC` 检查一次；每轮 `reload_config()` 从 `.env` 重读配置（界面保存后立即生效）。
  - **不补发**：启动时把当天已过且未触发的时段直接标记为已触发，不执行。
  - 每个时段一次性：任何一次尝试（成功/失败/达上限/未登录）都记入 `logs/auto_state.json`（`{"date", "fired"}`），当天不再重复。
- `articles_today_count()`：统计 `logs/publish_history.jsonl` 中**当天发布成功**的记录数（自动与手动都记录，`--dry-run` 不记录）。
- `publish.record_publish()`：`publish.run()` 发布成功后追加 `{time,title,visibility,source}` 到 `logs/publish_history.jsonl`。
- `cleanup_empty_archives()`：清理 `articles/` 下无 `article.json` 且超过 10 分钟的空目录。
- `pick_topic()`：`pool_first`/`pool_only` 读 `topics.txt`；池空且允许 AI 时，用 `history.recent_prompt_block()` 调 `generate.suggest_topics()`（实时参考默认关闭）。
- 日志：`make_logger()` 统一加时间戳，输出到 GUI 回调/控制台并写 `logs/auto_YYYYMMDD.log`。
- GUI 端「自动」页签：后台线程跑 `loop()`；状态显示“下次触发时间”和“今日已发布 X/上限 Y”；提供「立即执行一次」（遵守上限）与「强制执行一次（忽略上限）」。

### 5.7 MiniMax 繁转简（translator.py）

- 接口：`POST {MINIMAX_BASE_URL}/chat/completions`，`Authorization: Bearer <MINIMAX_API_KEY>`，OpenAI 兼容。
- `translate_blocks()`：图片块转 `[[IMGn]]` 占位符，与文本一起整篇翻译，再按占位符还原图文顺序；占位符丢失/错序则回退逐段翻译（图片位置不变）。剥离 `<think>` 推理块。
- 清理提示词：`SYSTEM_PROMPT` 要求「转简体 + 删除署名/订阅/推广/免责等非正文段；不确定保留；正文事实/数字/标点/英文/专有名词不改；`[[IMGn]]` 原样保留」。模型误删含图标记段时，占位符校验失败即回退逐段翻译（仍由 `sites/` 规则兜底），不会图文错位。
- `translate_title()`：标题单独繁转简，失败回退原文（不拖垮整篇）；`news_pipeline` 在正文翻译后同步转换标题，使 frontmatter、`meta.json` 与公众号草稿标题一致。作者与来源保留原文。
- `translate_text()` 长文按 `TRANSLATE_CHUNK_CHARS` 在段落边界分段后拼接。
- `entity_terms()`：让 MiniMax 从**标题+正文**提取 `(公司名, 人名, 其他关键词)`（JSON，容错回退空列表），供正文配图按「公司→人名→关键词」顺序检索。
- 自检：`python translator.py`（占位符还原、异常回退判定、分段逻辑）。

### 5.8 微信公众号发布（wechat.py / wechatsync）

- 工具：[Wechatsync](https://github.com/wechatsync/Wechatsync) CLI（`@wechatsync/cli`），走 Chrome 扩展的浏览器登录态，默认存草稿。
- 命令：`wechatsync --timeout <ms> sync <md> -p <platforms> -t <title> [--cover <本地路径|URL>] [--dry-run]`；凭据环境变量 `WECHATSYNC_TOKEN`，端口 `SYNC_WS_PORT`。
- 关键实现点：
  - **退出码不可靠**：同步成败恒 `exit(0)`，`wechat.py` 解析 stdout 的 `N 成功 / M 失败` 与 `✓/✗` 判定；连接扩展失败才是 `exit(1)`。
  - **进程调用（Windows）**：`_cli_prefix()` 优先解析 `node.exe + node_modules/@wechatsync/cli/dist/index.js` **直接以 node 启动**（避免 `.cmd → cmd.exe → node` 的孙进程继承管道）；解析失败才回退 `.cmd`。
  - **超时杀进程树**：`_run()` 用 `Popen(CREATE_NEW_PROCESS_GROUP)` + `communicate(timeout)`，超时用 `taskkill /F /T /PID` 杀掉整棵树后再收尾；确保 GUI 一定恢复、**不残留 node 占用 9527**（旧实现超时后可能卡在管道收尾且遗留孤儿进程）。
  - **隐藏窗口 + 清理残留**：`_process_flags()` 默认加 `CREATE_NO_WINDOW`（`WECHATSYNC_SHOW_CONSOLE=true` 时显示窗口便于排查）；`_cleanup_stale_bridge()` 在 `auth`/`sync` 前清理命令行含 `@wechatsync` 的残留 node（不误杀其它 node），避免新实例进 secondary 空等、重试无响应。
  - **平台兜底**：`WECHATSYNC_PLATFORMS` / 入参为空时一律回落 `weixin`；空平台会让 CLI 走「列出所有平台」分支，输出同时含「已登录/未登录」而误判成未登录。
  - **Token 错误识别**：`auth` 输出含 `Invalid or missing token` 直接抛 `WechatError`（提示 Token 无效/缺失），非 0 退出码也抛错；不再被 `is_logged_in()` 误判为「未登录」。
  - **stdin 预答 "n"**：CLI 在主桥等不到扩展时会交互询问「是否打开扩展安装页?」。若 stdin 关闭，readline 的 `close` 不会触发 `question` 回调 → Promise 永不 resolve → CLI 既不退出也不 `bridge.stop()`，**长期占着 9527/9528**（正是"超时后仍残留 node 进程"的根因）。现在 `_run()` 用 `stdin=PIPE` 并 `communicate(input="n\n")` 预答「否」，CLI 打印安装指引后立即 `exit(1)`。
  - **桥接预检**：`bridge_status()` 读 CLI 的 HTTP API `GET http://127.0.0.1:<SYNC_WS_PORT+1>/status`（`trust_env=False` 强制直连，避免系统代理干扰；2s 超时），返回 `True` 已连扩展 / `False` 有实例但扩展未连 / `None` 无实例或探测失败。`check_login()`、`publish_file()` 在启动 CLI 前调用 `_ensure_bridge_connected()`：若为 `False` 则**立即报错**（提示开启扩展「MCP 连接」）并顺手清理占用端口的旧实例，不再白等 45s/600s。
  - **超时错误带 CLI 输出**：超时杀进程后，把已捕获的 stdout/stderr 尾部（≤300 字）并入 `WechatError`，便于直接看到 CLI 原话（如安装指引、`连接超时: 已有实例正在运行但 Chrome Extension 未连接`）。
  - 本地图片：Markdown 用相对路径引用 `img_*.jpg`，wechatsync 会把本地图片上传到目标平台图床；封面经 `--cover` 传本地绝对路径。
  - `--timeout` 控制等待扩展连接，须置于子命令之前；`sync` 与 `auth` 均会传入。
- 登录态：`wechat.check_login()` 调 `wechatsync --timeout <ms> auth <platform>`（默认 `weixin`），子进程超时 `WECHATSYNC_AUTH_TIMEOUT_SEC`（默认 45s，超时杀进程树）；`is_logged_in()` 解析「已登录/未登录」，GUI 失败时显示「检查失败」而非「未登录」。

### 5.9 留档与历史

- `news_pipeline.run()` 每篇写入 `wechat_articles/<时间戳>_<序号>_<slug>/`：`article.md`、`img_*.jpg`、`meta.json`。
- 配图：`download_images()` 下载正文已有图；`add_auto_images()` 在正文**无任何图**时，用 `translator.entity_terms()` 提取的公司/人名/关键词按「公司→人名→关键词」检索图库，补 `[NEWS_AUTO_IMAGE_MIN, NEWS_AUTO_IMAGE_MAX]` 张，按内容哈希去重、**均匀插入各文本段之后**；**图库完全无命中**时用 `imagegen.generate_body_images()`（主体=公司名+人名或标题）生成图片再插入。生成张数受 `NEWS_AUTO_IMAGE_GEN_MAX`（默认 2）限制、单张超时 `MINIMAX_IMAGE_TIMEOUT`（默认 60s），并有逐张进度日志；生成失败则跳过、**不阻断发布**（最坏耗时被 上限×超时 封顶）。
- 封面 `_resolve_cover(article, out_dir, log, source_cover=...)` 优先级：文章**自身图**（`source_cover`，在自动补图前记录）→ `imagegen.generate_cover()` **MiniMax 文生图** → `WECHAT_DEFAULT_COVER` → 无封面（记日志，不阻断）。文章自身无图时**不使用自动补的图库图当封面**。
- `run(selected=[...])`：传入指定 `NewsItem` 时只发布这几篇（跳过 `list_items` 与随机抽取），供 GUI「发布选中」使用；不传维持随机批量。
- `list_candidates(site_key)`：抓取候选列表，供 GUI 刷新下拉框。
- 发布成功后追加 `logs/wechat_publish_history.jsonl`（`time/title/url(草稿链接)/source_url(原文链接)/source/dir`）。
- `published_source_urls()`：读取历史中的 `source_url`（老记录缺该字段时回退其 `dir/meta.json`），返回已发布原文链接集合；GUI 用它把已发布候选从下拉框排除。
- 单篇失败仅记日志并继续，整批不中断；`--dry-run` 不记录发布历史、也不计入已发布。

### 5.10 封面文生图（imagegen.py）

- 接口：`POST {MINIMAX_BASE_URL}/image_generation`，`Authorization: Bearer <MINIMAX_API_KEY>`。
- Body：`model`=`MINIMAX_IMAGE_MODEL`（默认 `image-01`）、`prompt`（标题套模板，≤1500 字）、`aspect_ratio`=`WECHAT_COVER_ASPECT`（默认 16:9）、`response_format=base64`、`n=1`、`prompt_optimizer=true`。
- 返回 `data.image_base64[0]` 解码落盘 `wechat_articles/.../cover_ai.jpg`；`base_resp.status_code` 非 0 或异常抛 `ImageGenError`；`MINIMAX_IMAGE_MODEL` 留空视为关闭（`generate_cover` 返回空串）。
- `generate_body_images(subjects, count, out_dir)`：正文图库完全无命中时，逐张生成 `auto_gen_N.jpg`（prompt 含公司/人名等主体），张数受 `NEWS_AUTO_IMAGE_GEN_MAX`（默认 2）限制，单张超时 `MINIMAX_IMAGE_TIMEOUT`（默认 60s）；每张前后记日志，单张失败则跳过。
- 自检：`python imagegen.py`（monkeypatch `requests.post`，离线）。

### 7.1 Defender 误报 leakless.exe

**现象**：双击或点击「扫码登录」被 Microsoft Defender 拦截；程序报错 `fork/exec ...\leakless-amd64-<hash>\leakless.exe: Operation did not complete successfully because the file contains a virus`。

**原因**：xiaohongshu-mcp 基于 go-rod，启动浏览器时会释放辅助进程 `leakless.exe` 到 `%LOCALAPPDATA%\Temp\leakless-amd64-<hash>\`。Defender 的启发式规则将其误报为 `Trojan:Win32/Kepavll!rfn` 并查杀。

**关键**：拦截是由 **`leakless.exe` 自身进程**发起的（Defender 事件“进程名称”就是 `leakless.exe`，有时是 `svchost.exe` 或 `MSPCManagerService.exe`）。因此仅排除 `xiaohongshu-*.exe` 进程或项目目录**无效**，必须排除 **leakless 所在目录**。官方 Windows 指南亦如此要求。

**微软电脑管家**：`Microsoft PC Manager` 会调用 Defender 引擎拦截同一 `leakless.exe`（事件进程名 `MSPCManagerService.exe`）。正确添加 Defender 排除后通常即生效；若仍被拦，在「微软电脑管家 → 设置/病毒防护」添加信任/排除，或临时关闭其实时防护。

**解决**（管理员 PowerShell）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\allow_defender.ps1
```

脚本会：自动发现并对 `%LOCALAPPDATA%\Temp\leakless-amd64-*` 目录添加路径排除（找不到则用官方已知路径 `...\leakless-amd64-adb80298fa6a3af7ced8b1c9b5f18007`）、清理 Temp 残留、并附带项目目录与进程排除，最后打印验证结果。之后到 Defender「保护历史记录」把 `leakless.exe` 条目「允许/还原」，重启登录与 MCP 服务。

**备选**：仅排除该 leakless 目录即可；如需避免依赖排除项，可用官方 Docker 版本（容器内为 Linux，不释放 `leakless.exe`），代价是需 Docker Desktop 且扫码配置更复杂。

**安全说明**：排除项会降低防护，仅建议对**官方来源**的二进制使用；优先只排 leakless 目录，不要无必要地排除整个 `Temp`/`Downloads`。

### 7.2 发布卡死修复（PR #846 补丁编译）

**现象**：发布图文时，服务端日志停在 `正文填写完成，准备等待后回点标题输入框`，约 5 分钟后报 `回点标题输入框失败: context deadline exceeded`，笔记未发出。官方 v2.5.0 存在该 Bug（issue #837），修复 PR #846 尚未合并发版。

**根因**：`waitAndClickTitleInput` 用 `humanize.Click → WaitInteractable()`，标题框被滚动出视口或被 Tiptap 联想浮层遮挡时会无限轮询直到超时。

**本项目做法**：用 PR #846 分支源码自行编译 `xiaohongshu-mcp-windows-amd64.exe`（补丁改为 `ClickNoWait` + `Focus` 兜底）。原版已备份为 `xiaohongshu-mcp-windows-amd64.v2.5.0.bak.exe`。

**可复现编译步骤**（Windows，Go ≥ 1.24）：

```powershell
# 1) 解压 go1.24.13.windows-amd64.zip 到 D:\dev_tools\Golang\go1.24.13
# 2) 拉源码并切到 PR #846
git clone https://github.com/xpzouying/xiaohongshu-mcp
cd xiaohongshu-mcp
git fetch origin pull/846/head:fix846
git checkout fix846
# 3) 编译（显式指定 GOROOT，避免用到旧版 Go）
$env:GOROOT = "D:\dev_tools\Golang\go1.24.13"
$env:GOTOOLCHAIN = "local"
$env:GOPROXY = "https://goproxy.cn,direct"
$env:CGO_ENABLED = "0"
& "D:\dev_tools\Golang\go1.24.13\bin\go.exe" build -o xiaohongshu-mcp-windows-amd64.exe .
```

**配套客户端设置**：`PUBLISH_TIMEOUT_SECONDS=330`（大于服务端 300s 内部上限，避免客户端提前断开）；`XHS_REFERENCE_ENABLED=false`（`search_feeds` 近期会 panic，见 issue #836，且会拖垮浏览器会话）。

**验证**：服务端日志出现 `已回点标题输入框（ClickNoWait 路径）` 并最终 `发布成功，已跳转离开发布页`，实测约 83s。

**回退**：改用备份的 `xiaohongshu-mcp-windows-amd64.v2.5.0.bak.exe`。
